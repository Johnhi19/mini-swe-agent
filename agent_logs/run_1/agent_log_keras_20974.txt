DescriptionA recent optimization PR replaced the manual NumPy sliding-window convolution loop in gaussian_blur with scipy.signal.convolve2d(..., mode="valid") to improve performance.
While this optimization works flawlessly for odd-sized kernels, it introduces an off-by-one spatial dimension mismatch regression when processing even-sized kernels (e.g., kernel_size=(4, 4)). This causes a hard 
crash (ValueError: could not broadcast) during execution because the output matrix dimensions generated by SciPy no longer fit the original pre-allocated tensor slices.

Minimal Reproducible Example
Python
```
import numpy as np
import keras
from keras.src.backend.numpy.image import gaussian_blur

print(f"Keras Version: {keras.__version__}")

# Create a simple 12x9 input image with 3 channels
dummy_image = np.random.rand(1, 12, 9, 3).astype(np.float32)

# Calling gaussian_blur with an even-sized kernel triggers the regression
output = gaussian_blur(dummy_image, kernel_size=(4, 4), sigma=(1.0, 1.0))
```

Technical Root Cause Analysis
The regression is an unintended side effect of switching the underlying convolution backend without accounting for spatial alignment behavior on even dimensions:

1. Pre-PR Implementation (Manual Window Loop)
- Padding: Calculates padding via integer division: pad_h = kernel_size[0] // 2. For a 4x4 kernel, pad_h = 2 and pad_w = 2.
- Sizing: An input of (12, 9) yields a padded size of (12 + 4, 9 + 4) = (16, 13).
- Execution: The manual loop bounds are locked explicitly to the original bounds: for i in range(height) and for j in range(width). This forces the output to strictly preserve the original spatial dimensions of (12,
9).

2. Post-PR Implementation (scipy.signal.convolve2d)
- Padding: Uses the identical padding logic, generating a (16, 13) matrix.Execution: Calls scipy.signal.convolve2d(padded, kernel, mode="valid").
- The Math Breakdown: For a valid convolution, the math follows $P_{\text{size}} - K_{\text{size}} + 1$.Height: $16 - 4 + 1 = 13$Width: $13 - 4 + 1 = 10$
